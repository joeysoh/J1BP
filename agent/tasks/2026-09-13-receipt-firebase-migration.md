# Migrate receipt scanning from Vercel API + B2 to Firebase-only SPA

## Assumptions and clarifications

- Originally scoped as "add logging to api/upload-receipt"; during planning the user redirected this to a full architecture migration, so that logging task is superseded and replaced by this one.
- **OAuth provider**: Google Sign-In via `signInWithPopup`/`GoogleAuthProvider` — the standard, lowest-friction choice for Firebase web OAuth. `vercel.json` already sets `Cross-Origin-Opener-Policy: same-origin-allow-popups`, which is exactly what a popup-based Google sign-in needs. Flag if a different provider (email link, etc.) was intended instead.
- **Keying by uid, not raw email**: Realtime Database keys cannot contain `.` (or `#$[]`), so a raw email address can't be used directly as a path segment. The plan uses the authenticated user's **uid** as the path key (`receipts/{uid}/{pushId}`), which is also what security rules need to check (`auth.uid`) for real enforcement — the user's email is still stored as a *field* inside the entry (for the external script to use/display).
- **No Firebase Storage** — the user explicitly does not want it. The receipt image is converted to a base64 string (already how `resizeImageToDataUrl` works) and stored directly as a field inside the Realtime Database entry.
- **Rule deployment is a manual step**: this task authors `database.rules.json` in the repo, but actually publishing it (`firebase deploy --only database`) is done by the user via Firebase CLI/console — not automated here, since there's no `firebase.json`/CLI project wiring in the repo today and setting up deploy credentials is out of scope.
- **External script contract**: a separate script, external to this repo, will watch Realtime Database, perform OCR extraction, and write results back. This task only defines and documents the data contract it must honor (an RTDB entry schema with an `image` field holding the base64 string, plus a `status` field) — it does not implement that script.
- **Base64-in-RTDB size**: the existing `resizeImageToDataUrl` already caps images at 1280px / JPEG quality 0.75, keeping the base64 string well under Realtime Database's per-node size limits.
- **Timeout handling**: a basic client-side timeout (e.g. 2 minutes) is added while waiting for the external script to fill in results, surfacing an error if it never responds.
- `firebase.config.js` at the repo root appears to be an unused/orphaned duplicate of `src/firebase.js` — left untouched unless asked to remove it.

## Result

Receipt scanning no longer depends on a Vercel serverless function, Backblaze B2, or a direct Ollama call from this repo. The app is now a pure static SPA that:
- Requires Google sign-in (Firebase Auth) before the "+Receipt" control even appears.
- Converts the photo to a base64 string client-side (unchanged resize/compress step) and pushes it as a pending entry to Firebase Realtime Database under `receipts/{uid}`, protected by security rules so only that user can read/write their own entries.
- Listens for the same entry to be updated (by a script outside this repo) with `status: 'done'` and `items`, then prefills the bill — or times out after ~2 minutes with an error if nothing shows up.

`api/upload-receipt.js` and its two dependencies (`@aws-sdk/client-s3`, `ollama`) are removed; `vercel.json` needed no changes. The RTDB entry contract (`email`, `image`, `status`, `createdAt`, `items`, `doneAt`) is documented as a single source of truth in `agent/design/receipt-schema.md` for whoever builds the external extraction script, and `agent/design/current.md` reflects the new architecture end-to-end.

**Still open**: a real, fully authenticated end-to-end run (sign in for real → upload a photo → manually complete the entry in the Firebase console → confirm the bill prefills) hasn't been confirmed, since that needs a real Google account, which the agent doesn't have. Everything short of that has been verified: build, unit tests, RTDB read/write with `example.jpg`-sized payloads, and confirmation that security rules are deployed and correctly reject unauthenticated access.
